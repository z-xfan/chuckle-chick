# REQ-0017：扩展 JX3API 骚话与随机决策内容

## 基本信息

- 状态：已完成
- 创建日期：2026-08-17
- 最后更新：2026-08-18
- 负责人：待定

## 背景

REQ-0012 已在快捷面板的“骚话”二级页面接入 JX3API 的“随机骚话”和“舔狗日志”。JX3API 的“骚话语录”分类现已提供“答案之书”“分类语录”“喝什么”“吃什么”和“渣男语录”五个新接口，用户希望将新增内容一并放入现有功能。

这些接口并非全部都是同一类内容：随机骚话、舔狗日志、渣男语录和分类语录的核心用途是快速取得并复制文案；答案之书、吃什么和喝什么则是在帮助用户做一个轻量决定。为避免复制型语录被埋到更深层级，本需求保留现有“骚话”入口，并为后三项增加一个独立的快捷面板入口。

分类语录要求选择分类并提供 `LV.2` Token。项目当前没有 `LV.2` Token，因此本需求明确不接入分类语录。

## 目标

- 用户可以从现有“骚话”入口直接访问各种可复制语录，不增加中间分类页面。
- 用户可以从快捷面板的新入口访问答案之书、吃什么和喝什么。
- 根据内容类型清楚展示单句、答案组合或多个候选项。
- 保留现有的刷新、复制、加载、错误恢复和第三方来源提示能力。
- 不引入 Token 配置或付费接口，保持本期新增能力无需用户登录或配置凭证。

## 范围

### 包含

- 扩展现有“骚话”二级页面，加入渣男语录。
- 在快捷面板首页增加一个暂定名为“小决定”的入口，并在对应二级页面放置答案之书、吃什么和喝什么。
- 两个二级页面均复用现有辅助窗口，不创建新的 Tauri 窗口。
- 接入以下 `LV.0` 接口：
  - `saohua/answer`（答案之书）；
  - `saohua/drink`（喝什么）；
  - `saohua/eat`（吃什么）；
  - `saohua/zhanan`（渣男语录）。
- 保留现有 `saohua/random`（随机骚话）和 `saohua/content`（舔狗日志）。
- 为不同响应结构提供统一的应用内模型和对应展示。
- 支持刷新当前类型、复制当前完整结果，并保留现有请求冷却、超时和并发互斥约束。
- 更新与扩展相关的 Rust 适配器、前端类型、页面交互和自动化测试。

### 不包含

- 不为答案之书、吃什么和喝什么分别增加快捷面板首页入口。
- 不在“骚话”和具体语录之间增加“语录”等中间页面。
- 不自动推荐附近餐厅、饮品店，不使用定位、外卖或地图服务。
- 不允许用户编辑 JX3API 的食物、饮品、答案或语录库。
- 不提供收藏、历史记录、分享或自动发送到其他应用。
- 不把远程结果自动展示为宠物气泡或系统通知。
- 不在仓库、前端资源或发行包中硬编码共享 JX3API Token。
- 不为接入分类语录而代用户购买或生成 JX3API Token。
- 不接入 `saohua/context`（分类语录），不展示分类语录入口，也不提供 `LV.2` Token 配置。

## 已确认信息架构

语录与随机决策分成两个快捷面板入口：

```text
快捷面板

[ 骚话 ]  →  随机骚话 / 舔狗日志 / 渣男语录
[ 小决定 ] →  答案之书 / 吃什么 / 喝什么

骚话页面

[ 随机 | 舔狗 | 渣男 ]

┌────────────────────┐
│ 当前完整文案        │  ← 点击整卡可复制
└────────────────────┘

[复制]                    [换一句]

小决定页面

[ 答案之书 | 吃什么 | 喝什么 ]

┌────────────────────┐
│ 当前结果            │
└────────────────────┘

[复制]                    [换一个]
```

- “骚话”名称和入口保持不变，点击后直接看到具体语录类型，满足快速获取和复制。
- 答案之书、吃什么和喝什么合并到一个新的快捷入口；入口暂定名为“小决定”。
- 两个二级页面都只保留一级类型选择，不再进入第三层页面。
- 骚话页面默认仍选择随机骚话，保持现有用户路径不变。
- 分类语录不在页面展示入口或占位状态。

## 核心用户流程

### 骚话与语录

1. 用户从快捷面板点击现有“骚话”入口，直接进入语录页面。
2. 页面默认显示“随机骚话”，沿用当前运行期最近结果或首次自动请求。
3. 用户在同一页直接选择随机骚话、舔狗日志或渣男语录。
4. 用户可以复制完整文案，或点击“换一句”请求当前类型的新结果。

### 小决定

1. 用户从快捷面板点击新增的“小决定”入口。
2. 用户在同一页选择答案之书、吃什么或喝什么，不再进入下一级页面。
3. 首次访问某个类型时按该类型的交互规则请求；已有当前运行期结果时先展示旧结果。
4. 用户可以复制完整结果，或请求当前类型的新结果。

### 答案之书

1. 页面提示用户先在心中想好一个问题。
2. 用户主动点击“翻开答案”后才调用接口，避免进入类型即提前揭示答案。
3. 结果将 `answer` 作为主文案，将 `hearten` 作为附加鼓励语分别展示。
4. 复制时按“答案 + 换行 + 鼓励语”生成完整纯文本。

### 吃什么与喝什么

1. 用户选择“吃什么”或“喝什么”。
2. 页面展示接口本次返回的全部候选项，不擅自只取其中一项。
3. 复制时按每项一行生成完整纯文本。
4. “换一组”重新请求当前类型的候选列表。

## 需求说明

### 1. 导航与类型选择

- 保留现有“骚话”入口，新增一个“小决定”入口；不增加更多本需求相关的快捷面板入口。
- “骚话”点击后直接展示具体语录选择，不设置“语录”中间分类。
- “小决定”点击后直接展示答案之书、吃什么和喝什么三个选择，不设置第三层页面。
- 两页的类型选择必须适配 `360 × 420` 窗口，不能依赖被截断的横向滚动才能发现功能。
- 每次进入骚话页面默认选中随机骚话；现有随机骚话和舔狗日志行为不回退。
- 小决定页面的默认项在视觉方案中确定，但答案之书不得因进入页面而自动揭示结果。
- 每个具体类型分别保存应用运行期间最近一次成功结果，不跨应用重启持久化。
- 类型切换不得混用其他类型的结果、加载态或错误态。

### 2. 结果展示与复制

- 单句语录完整换行展示，沿用正文卡片交互。
- 答案之书分别展示答案与鼓励语，不丢弃任何一个有效字段。
- 吃喝结果展示全部有效候选项，并保持上游顺序。
- 复制按钮与整卡复制继续可用；多字段和数组结果按本需求定义的纯文本格式复制。
- 所有远程字符串去除首尾空白，只按纯文本渲染，不解析 HTML、Markdown、链接或表情短代码。
- 任一必需字段为空、类型不符、数组为空或超过安全上限时，视为无效响应。

### 3. 请求与错误处理

- 网络请求继续由 Rust 平台层发起，Vue 不直接请求 JX3API。
- 每个具体类型同时只允许一个请求，并保留至少 `1` 秒冷却与 `10` 秒建议超时。
- 刷新失败时保留该类型已有的成功结果；没有旧结果时展示可重试错误。
- HTTP 错误、业务 `code` 非 `200`、缺少字段、无效空内容和超长内容均需安全处理。
- 新增接口故障不能影响既有两类语录、宠物行为或其他快捷功能。
