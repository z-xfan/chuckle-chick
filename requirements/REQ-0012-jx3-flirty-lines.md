# REQ-0012：骚话文案

## 背景

当前宠物快捷面板已承载多个剑网 3 实用功能，但缺少轻量、偏娱乐的互动内容。JX3API 提供随机骚话和舔狗日志两个无需业务参数的接口，可以让用户快速获取一句文案并复制到剪贴板。

两类内容的使用目的相同，都是“获取一句可复制的文案”。如果在快捷面板首页分别增加两个入口，会挤占有限空间，也会放大同类功能的视觉权重。因此本需求只增加一个“骚话”入口，在二级页面内切换“随机骚话”和“舔狗骚话”。

## 目标

- 用户可以从宠物快捷面板通过一个入口进入骚话页面。
- 用户可以在随机骚话和舔狗骚话之间切换，并获取对应内容。
- 用户可以清楚、快速地复制完整文案，也可以继续换一句。
- 网络或剪贴板操作失败时提供可恢复反馈，不影响宠物及其他快捷功能。

## 范围

### 包含

- 在现有宠物快捷面板增加一个“骚话”入口。
- 在当前辅助窗口内进入骚话二级页面，不创建新的 Tauri 窗口。
- 提供“随机骚话”和“舔狗骚话”两种类型切换。
- 分别调用 JX3API `saohua/random` 和 `saohua/content` 接口。
- 完整展示返回文案，并提供整卡复制、明确的复制按钮和“换一句”操作。
- 提供加载、刷新、复制成功、空内容和错误状态。
- 对同类请求进行并发互斥和短时间防重复点击。
- 明确标注第三方内容来源和内容提示。

### 不包含

- 不为两种骚话分别增加快捷面板首页入口。
- 不接入 JX3API 付费 Token，也不要求用户登录。
- 不提供文案搜索、编辑、收藏、历史记录或本地持久化。
- 不提供自动发送到游戏、聊天软件或其他应用。
- 不在首版调用系统分享面板。
- 不主动推送骚话，不在后台定时请求。
- 不把远程文案自动显示为宠物气泡。
- 不对第三方文案进行改写、续写、分类或 AI 审核。

## 数据源调研

### 接口

```text
GET https://www.jx3api.com/saohua/random
GET https://www.jx3api.com/saohua/content
```

### 接口属性

- JX3API OpenAPI 将两个接口归类在“骚话语录”。
- `random` 的接口名称为“随机骚话”，当前等级为 `LV.0`。
- `content` 的接口名称为“舔狗日志”，当前等级为 `LV.0`。
- 两个接口均不需要业务参数。
- 2026-07-31 无 Token 实测两个接口均返回 `code=200`。
- 两个接口当前返回结构一致，正文位于 `data.text`。
- 实测舔狗日志通常比随机骚话更长，可能包含粗口、贬损表达或其他不适合所有用户的第三方内容。

### 当前响应结构

```text
code: number
msg: string
data:
  text: string
time: number
```

### 来源

- `https://www.jx3api.com`
- `https://www.jx3api.com/saohua/random`
- `https://www.jx3api.com/saohua/content`

## 核心用户流程

1. 用户单击宠物打开现有快捷面板。
2. 用户点击唯一的“骚话”入口。
3. 应用在当前辅助窗口内打开骚话二级页面，默认选择“随机骚话”。
4. 页面自动获取并展示一句随机骚话。
5. 用户可以点击文案卡片或“复制”按钮复制完整文案。
6. 页面显示短暂的“已复制”反馈，但不自动关闭。
7. 用户可以点击“换一句”，或切换到“舔狗骚话”后获取对应内容。

## 需求说明

### 1. 入口与导航

- 快捷面板首页只增加一个“骚话”入口。
- 点击入口后在现有辅助窗口内进入二级页面，不创建新窗口或新 WebView。
- 页面提供明确的返回快捷面板和关闭辅助窗口操作。
- 返回后再次进入时，在同一次应用运行期间可以恢复两种类型各自最近一次成功获取的内容。
- 不持久化上次内容；应用重启后重新获取。

### 2. 类型选择

- 页面顶部提供“随机骚话”和“舔狗骚话”两个分段选择项。
- 每次进入页面默认选中“随机骚话”，不持久化类型选择。
- 首次进入时自动请求随机骚话，减少一次无意义点击。
- 用户切换类型时：
  - 当前运行期间该类型没有成功内容，则立即请求；
  - 已有成功内容，则先展示该内容，不自动刷新；
  - 用户可以点击“换一句”明确请求新内容。
- 切换期间不得将另一类型的内容冒充为当前类型结果。

### 3. 内容展示

- 文案使用一个主要内容卡片完整换行展示。
- 不使用省略号截断远程正文；页面空间不足时在内容区域内部滚动。
- 远程正文只按纯文本渲染，不解析 HTML、Markdown、链接或表情短代码。
- 去除正文首尾空白；空字符串或只有空白的内容视为无效响应。
- 为异常响应设置合理的最大文本长度保护；超限时不展示、不复制，并提示内容暂时不可用。
- 页面明确标注“内容来自 JX3API（第三方）”。
- 页面提供简短内容提示，例如“第三方随机文案可能包含粗口或冒犯表达”。
- 远程文案只在用户主动进入页面后展示，不作为宠物主动气泡或系统通知出现。

### 4. 复制交互

- 内容卡片整体可点击复制，满足高频操作的一步完成。
- 卡片旁或卡片底部同时保留文字明确的“复制”按钮，避免用户不知道卡片可点击，并满足键盘操作。
- 复制的是当前卡片内未经截断的完整纯文本。
- 复制成功后：
  - 复制按钮短暂显示“已复制”；
  - 页面提供不打断操作的状态反馈；
  - 页面保持打开，当前内容不变化。
- 复制失败时显示明确错误，并允许再次尝试。
- 内容仍在加载、为空或请求失败时，复制操作不可用。
- 卡片和复制按钮均支持键盘聚焦；按 `Enter` 或 `Space` 可以复制。
- 首版不因复制成功自动再取一句，避免用户尚未核对内容就被替换。

### 5. 换一句与请求控制

- 页面提供主要操作“换一句”。
- “换一句”只请求当前选中的类型。
- 同一类型同时只允许一个请求；请求期间按钮进入加载状态，不重复发起请求。
- 连续点击设置至少 `1` 秒的前端冷却，避免误触造成短时间大量请求。
- 请求建议超时为 `10` 秒。
- 成功获取新内容后替换当前类型的旧内容。
- 请求失败时保留当前类型已有的成功内容，并在其旁提示刷新失败。
- 没有成功内容且请求失败时显示错误状态和“重试”操作。
- 本需求不设置跨应用重启的缓存，也不后台预取下一句。

### 6. 状态与错误

- 页面区分首次加载、换句中、成功、无效空内容、请求失败和复制失败。
- JX3API 返回 HTTP 成功但业务 `code` 非 `200` 时视为失败。
- 响应缺少 `data.text`、字段类型错误或内容非法时视为无效响应。
- 上游错误不得清空当前已成功展示的内容。
- 骚话页面错误不得影响宠物动画、拖动、快捷面板其他功能或应用退出。

### 7. 数据与安全边界

- 网络请求由 Rust 平台层负责，Vue 不直接跨域请求 JX3API。
- 只允许访问以下两个精确的 HTTPS 地址：
  - `https://www.jx3api.com/saohua/random`
  - `https://www.jx3api.com/saohua/content`
- 不读取、保存或发送用户账号、Cookie、Ticket、Token、剪贴板原内容及其他个人信息。
- 只有用户执行复制操作时才写入系统剪贴板。
- 不记录用户获取或复制过的远程文案。
- JX3API 为第三方数据源，不将其内容表述为西山居或项目官方内容。

## 推荐交互方案

```text
← 骚话

[ 随机骚话 | 舔狗骚话 ]

┌────────────────────┐
│                    │
│   当前完整文案      │  ← 点击整卡可复制
│                    │
└────────────────────┘

[复制]                    [换一句]

内容来自 JX3API（第三方）
第三方随机文案可能包含粗口或冒犯表达
```

保留显式“复制”按钮比只做“点击正文复制”更容易发现，也更适合键盘用户；同时让整张内容卡片可点击，仍能保持用户期望的一步复制。“换一句”与复制分离，避免复制后内容突然改变。系统分享会带来不同平台行为差异，首版仅做剪贴板复制更稳定。
