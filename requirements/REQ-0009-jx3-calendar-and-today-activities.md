# REQ-0009：剑网 3 日历与今日活动

## 基本信息

- 状态：待验收
- 创建日期：2026-07-30
- 最后更新：2026-07-31
- 负责人：待定

## 背景

当前快捷面板已经能够查看《剑网 3》官方公告、武学调整和服务器状态，但用户仍需要进入游戏、官网或第三方工具才能确认“今天做什么”和近期有哪些活动。

`qsc20001102/astrbot_plugin_jx3` 提供了日常、月历、日常预测、百战、扶摇及其他活动查询，证明将分散的游戏日历信息整理成统一视图具有实际使用价值。其当前实现主要依赖 JX3API 等第三方接口，适合借鉴产品结构、缓存和错误处理方式，不直接复制代码，也不能在未确认数据来源、鉴权和稳定性之前直接接入。

桌面宠物适合承载轻量、高频的信息查看。用户点击黄鸡后即可快速确认今日内容，比完整攻略站或聊天机器人指令更直接。

## 目标

- 用户可以从现有宠物快捷面板进入“日历”二级页面。
- 用户可以查看当前日期的日常与已确认纳入范围的活动。
- 用户可以查看未来 `7` 天的日常预测，并在日期之间切换。
- 网络或数据源异常时提供明确反馈，并尽量展示最近一次成功数据。
- 数据展示保持轻量，不影响宠物动画、拖动和开服监听。

## 产品结构

- 在现有宠物快捷面板首页增加“日历”入口。
- 点击入口后，在当前辅助窗口内进入独立的“日历与今日活动”二级页面，不创建新的 Tauri 窗口。
- 二级页面提供：
  - 返回快捷面板首页；
  - 今日视图；
  - 今天至未来 `7` 天的日期切换；
  - 手动刷新。
- 页面一次只展示当前选择日期的内容，避免在小窗口中堆叠整月信息。

## 范围

### 包含

- 今日日期和星期。
- 今日游戏日常内容。
- 数据源能够明确提供日期、名称且稳定性满足要求的基础活动。
- 今天及未来 `7` 天的日常内容查询。
- 今日已确定内容与未来预测内容的明确区分。
- 当前日期与未来日期之间的切换。
- 数据规范化、排序、去重和空值处理。
- 本地缓存、手动刷新和离线降级。
- macOS 与 Windows 10/11 的基础展示和联网行为。

### 不包含

- 用户自行创建、勾选或同步个人任务清单。
- 角色维度的任务完成进度。
- 自动读取游戏客户端、账号或角色数据。
- 日历写入系统日历、Google Calendar 或其他第三方日历。
- 应用退出后仍运行的系统服务。
- 系统原生通知。
- 团队招募、交易行、奇遇、刷马和赤兔的详细查询。
- 百战、扶摇、诛恶等专项活动查询。
- 活动攻略、掉落表或完整正文在应用内展示。
- 需要抓包推栏 Ticket、绕过签名、验证码或其他访问控制的数据。

## 术语

### 日常

指数据源明确标识为某一游戏日可参与的轮换内容。首版固定展示大战、战场、阵营矿车、门派事件和驰援五类。

### 活动

指具有明确日期、时间范围或周期的基础游戏内容。首版只纳入能够稳定获得名称、日期和必要说明的项目；百战、扶摇、诛恶、刷马、赤兔等专项活动不纳入本需求。

### 预测

指数据源针对未来游戏日提供的推算内容。预测数据必须明确标记，不能表现为西山居已经确认的官方日程。

### 游戏日

游戏日使用中国标准时间，每日 `7:00` 开始，至次日 `6:59:59` 结束。凌晨零点至 `6:59:59` 仍属于前一个游戏日。

## 核心用户流程

### 查看今日内容

1. 用户单击宠物打开快捷面板。
2. 用户点击“日历”入口。
3. 应用进入日历二级页面。
4. 应用优先展示有效缓存；没有缓存时请求最新数据。
5. 页面展示今日日期、日常和活动。
6. 用户可以手动刷新。

### 查看未来日期

1. 用户在日历页面选择未来日期。
2. 应用展示该日期可稳定获得的日常预测或基础活动，并明确标注预测属性。
3. 如果数据源不提供对应日期，页面明确显示“暂无可用数据”，不能把请求失败显示为空内容。
4. 用户可以一键返回今天。

## 需求说明

### 1. 今日视图

- 页面顶部至少展示：
  - 当前选择日期；
  - 星期；
  - 数据更新时间。
- 内容按“日常”和“活动”分组；某组没有数据时保留明确的空状态。
- 今日数据与未来预测内容必须使用不同标识；两者都标明来自第三方数据源。
- 每条内容至少展示名称；可稳定获得时展示类型、开放时间、地图或简短说明。
- 远程文本按纯文本处理，不渲染 HTML。
- 相同日期、类型和名称的重复记录应合并。
- 列表内容过多时在页面内部滚动，不扩大透明窗口点击区域，不截断底部操作。

### 2. 日期范围

- 默认打开今天。
- 首版固定支持今天至未来第 `7` 天，共 `8` 个可选日期。
- 不默认请求整月全部数据。
- 仅在用户切换到对应日期时读取或计算该日期内容。
- 提供“回到今天”快捷操作。
- 不允许查询早于今天的历史日常；如后续需要历史记录，单独建立需求。

### 3. 展示字段

- 从 JX3API 响应中读取以下单值字段：
  - `war`：大战；
  - `battle`：战场；
  - `orecar`：阵营矿车；
  - `school`：门派事件；
  - `rescue`：驰援。
- 同时读取以下列表与周常字段：
  - `draw`：美人图；
  - `lucky`：宠物福缘；
  - `card`：家园声望加倍道具；
  - `leader`：世界boss；
  - `weekly.conn`：武林通鉴公共任务；
  - `weekly.raid`：武林通鉴团队秘境。
- 数组中的每个非空条目都必须展示；不得只保留第一项。
- 页面按“日常活动”和“轮换与周常”两个区域展示，避免十一类数据混成连续长列表。
- 大战、战场、阵营矿车、门派事件和驰援归入“日常活动”；其余内容归入“轮换与周常”。
- 每个分类使用独立卡片、简短识别标记和分类标题；同一分类的多个条目在卡片内以标签形式完整展示。
- 分区标题展示当前区域的条目总数，帮助用户快速判断数据量。
- JX3API 区间模式不返回 `weekly`，每次刷新额外请求一次今日详情并将 `weekly` 合并到今日数据；不为八个日期逐日发起请求。
- `weekly` 按北京时间自然周（周一至周日）解释：当前周剩余日期复用今日详情返回的武林通鉴内容。
- 未来日期进入下一自然周后，不把本周武林通鉴冒充为下周数据；页面显示“下周武林通鉴暂未公布”。
- 上游新增但本需求尚未定义语义的字段继续忽略，避免未经确认直接进入界面。
- 当前 JX3API 日历接口没有区服参数，REQ-0009 不增加服务器选择或默认服务器配置。
- 后续其他剑网 3 模块需要全局默认服务器时，应单独建立基础配置需求。

### 4. 刷新与缓存

- 首次打开且没有缓存时立即请求。
- 今日内容缓存到当前游戏日结束；跨越游戏日重置边界后立即失效。
- 未来预测内容缓存 `6` 小时；缓存有效时直接展示，不重复请求。
- 缓存过期时先展示旧数据，再尝试刷新。
- 用户手动刷新时忽略缓存新鲜时间。
- 连续手动刷新之间至少间隔 `60` 秒，避免在上游未公开限频规则时制造高频请求。
- 同一时间只允许一个日历刷新请求。
- 请求失败不得覆盖已有成功缓存。
- 缓存按数据日期隔离。
- 日期跨越游戏日重置边界后，今日缓存立即失效。
- 未来预测发生变化时使用最新成功数据替换旧预测，并更新数据时间。
- 缓存仅保存页面展示所需的规范化字段，不保存 Token、Cookie、网页脚本或完整网页。

### 5. 状态与错误

- 首次加载、刷新中、成功、合法空数据、离线缓存和请求失败必须使用不同状态。
- 无缓存且请求失败时提供重试入口。
- 有缓存但刷新失败时继续展示缓存，并标注“当前为上次数据”。
- 数据源缺少部分字段时展示可用内容，不能导致整个页面崩溃。
- 数据源只返回部分内容时展示已有数据，并明确提示“数据可能不完整”。
- 数据格式发生变化时记录开发日志，向用户展示通用的暂时不可用提示。
- 日历错误不得影响宠物、公告、技改、开服监听、设置和托盘。

### 6. 时间规则

- 所有业务日期和活动时间统一按中国标准时间 `Asia/Shanghai` 解释和展示。
- 如果上游返回 Unix 时间戳、带时区字符串或无时区文本，必须在 Rust 适配层统一转换。
- 每日 `7:00` 重置规则由用户确认，并得到西山居官方资料页佐证；该边界必须写入自动化测试。
- 应用启动、系统睡眠恢复和跨越重置时间后，应重新判断当前游戏日。

### 7. 主动提醒边界

- 首版只提供用户主动查看，不在后台轮询日历。
- 首版不发送系统原生通知。
- 首版不在每天首次启动时使用宠物气泡播报今日内容。
- 刷马、赤兔和其他实时事件推送不属于本需求，应单独建立提醒需求并评估轮询频率。

## 数据源边界

- 开发前必须确认日常和活动数据的实际来源，不因开源项目使用某接口就直接视为稳定依赖。
- 对每个候选来源分别确认：
  - 接口提供方和原始数据来源；
  - 请求地址、方法、参数和分页方式；
  - 是否要求 Token、付费套餐、登录或 Cookie；
  - 日常与未来日期字段的准确含义；
  - 游戏日重置时间及服务器差异；
  - 缓存、限频和使用条款；
  - Windows 与 macOS 网络环境下的可访问性。
- 如果西山居官方页面存在足够稳定的数据，优先使用官方来源。
- 如果只能使用 JX3API、JX3BOX 或其他第三方来源，必须在需求确认前明确：
  - 是否允许引入该运行时依赖；
  - 是否接受数据延迟或遗漏；
  - 是否需要用户自行提供 Token；
  - 第三方不可用时的降级行为。
- 不在应用中内置开发者私人 Token，也不把 Token 提交到仓库。
- 如果需要规避访问控制，本期停止接入并回到需求讨论。
- 网络请求由 Rust 平台层执行，Vue 只消费内部稳定模型。

### 数据源调研结论

- 2026-07-31 无 Token 实测 `GET https://www.jx3api.com/active/calendar?mode=day&num=0` 返回成功。
- JX3API 当前 OpenAPI 将活动日历标记为 `LV.0`，表示该接口不要求付费 Token。
- 旧路径 `active/list/calendar` 当前返回路径不存在，不能继续使用。
- 当前区间请求使用 `GET https://www.jx3api.com/active/calendar?mode=list&num=7`。
- `mode=list&num=7` 一次返回今天前后各 `7` 天；应用只保留今天至未来第 `7` 天的 `8` 条数据，不逐日重复请求。
- `mode=day&num=N` 可以单独查询偏移日期，`num` 当前允许 `0` 至 `15`；首版正常流程不需要逐日调用。
- 当前 OpenAPI 将接口描述为“单日或前后区间的日常活动推演”，因此未来内容必须标记为预测。
- 当前接口不接收服务器参数，日历数据按全服通用处理。
- JX3API 文档未公开该 `LV.0` 接口的具体限频值，HTTP 响应也未提供限频响应头；首版通过缓存、单请求和 `60` 秒手动刷新间隔保守使用。
- 西山居官网公开资料能够确认游戏内存在活动日历，并明确日常任务每日早 `7:00` 重置。
- 本次未发现西山居官网提供可直接替代的、面向第三方的当前日常结构化接口。官网资料页只适合确认规则，不能提供每天轮换数据。
- JX3API 是第三方运行时数据源，不代表西山居官方数据；页面需要显示数据来源，未来预测不能标记为官方确认。
- 无法仅通过公开资料验证未来预测的长期准确率；首版接受数据可能延迟或遗漏，并通过预测标记、更新时间和缓存降级控制风险。
- 参考资料：
  - `https://www.jx3api.com/`；
  - `https://www.jx3api.com/openapi`；
  - `https://jx3.xoyo.com/zl/new-jl.html`。

## 条目交互

- 首版条目只展示名称、类型、时间和可稳定获得的简短说明。
- 首版不为日常或活动条目提供详情页面。
- 首版不默认跳转第三方攻略。
- 后续只有在存在可靠的官方或可信来源链接，并完成域名允许列表确认后，才能增加系统浏览器跳转。

## 技术方案

- 在现有快捷面板首页增加日历入口，使用同一辅助窗口进入日历二级页面。
- Vue 负责日期切换、列表、来源、预测标记、缓存状态和错误展示。
- Rust 增加独立日历适配器，负责数据请求、日期转换、规范化、去重和缓存。
- Rust 只请求一次 JX3API 区间接口，再筛选今天至未来第 `7` 天。
- 日历数据源通过独立 Adapter 隔离，避免第三方字段直接进入界面。
- 日期归属、重置边界、去重、缓存和错误转换使用纯函数并编写自动化测试。

## 已确认决策

- [x] 在现有快捷面板中增加日历入口，并进入同一辅助窗口内的独立二级页面。
- [x] 首版包含今日内容和未来日期切换。
- [x] 未来日期范围固定为未来 `7` 天，不做完整月历。
- [x] 今日数据与未来预测内容必须明确区分，并显示第三方来源。
- [x] 日历页展示接口直接返回的基础日常、美人图、宠物福缘、家园加倍、世界boss和武林通鉴周常；不额外请求扶摇、诛恶、刷马、赤兔等专项接口。
- [x] 当前日历数据不区分服务器，REQ-0009 不增加服务器选择或默认服务器配置。
- [x] 游戏日按照 `Asia/Shanghai` 每日 `7:00` 切换。
- [x] 接受 JX3API `LV.0` 日历接口作为第三方运行时数据源，无需用户配置 Token。
- [x] 接受第三方数据可能延迟或遗漏；页面显示来源，未来数据明确标记为预测，接口不可用时使用缓存降级且不切换其他来源。
- [x] 今日缓存到游戏日结束，未来预测缓存 `6` 小时。
- [x] 首版条目不提供详情页面或外部攻略跳转。
- [x] 首版不做每日首次启动气泡播报，也不后台轮询日历。
- [x] 首版不包含个人任务勾选、角色完成进度和系统原生通知。
- [x] 不复制 `astrbot_plugin_jx3` 的 AGPL-3.0 源码，只借鉴产品和架构思路。

## 实施记录

- 在现有快捷面板增加“日历”入口，并复用辅助窗口进入“日历与今日活动”二级页面。
- 新增 Vue 日历页面，支持缓存优先加载、手动刷新、横向日期切换、今日/预测标识、完整活动分组展示以及过期、数据不完整和请求失败提示。
- 新增独立 Rust 日历适配器，通过 JX3API `active/calendar?mode=list&num=7` 获取区间数据，并通过 `mode=day&num=0` 补充只在今日详情返回的武林通鉴周常，完成日期过滤、字段规范化、去重、游戏日计算、缓存持久化和错误转换。
- 日历适配器向界面暴露大战、战场、阵营矿车、门派事件、驰援、美人图、宠物福缘、家园声望加倍道具、世界boss、武林通鉴公共任务和武林通鉴团队秘境；同类数组条目分组展示。

- 日历缓存结构升级到版本 `3`，自动丢弃缺少新增字段的旧版缓存，确保升级后首次进入日历会重新拉取完整数据。
- 当前周的武林通鉴条目在缓存规范化时传播到本周剩余日期；跨周日期通过 `weeklyPending` 明确通知界面展示待公布卡片，缓存结构升级到版本 `5`。
- 增加 `chrono` 时间依赖及异步刷新互斥；缓存写入应用配置目录下的 `jx3-calendar-cache.json`，手动刷新设置 `60` 秒请求冷却。
- 为 `7:00` 游戏日边界、字段白名单、未来预测标识、八日过滤、缓存过期和刷新冷却增加 Rust 自动化测试。
